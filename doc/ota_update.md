# Подготовка прошивки для OTA-обновления

Команды выполняются из корня проекта в терминале с активированным окружением
ESP-IDF 5.3.1. Можно использовать ESP-IDF Terminal в IDE.

## 1. Повысить версию

В корневом `CMakeLists.txt` изменить `PROJECT_VER` на следующую версию.
Например, если сейчас указано:

```cmake
set(PROJECT_VER "1.0.9")
```

для следующего обновления указать:

```cmake
set(PROJECT_VER "1.0.10")
```

Сохранить файл **до сборки**: это значение встраивается в прошивку.
Версию менять именно в корневом `CMakeLists.txt`, а не в `main/CMakeLists.txt`.

## 2. Собрать проект

```powershell
idf.py build
```

Дождаться успешного завершения. В выводе сборки проверить строку
`App "lvgl_porting" version: 1.0.10` (с выбранной версией).
Свежая прошивка появится в `build/lvgl_porting.bin`.

Если сборка завершилась с ошибкой, не заменять файлы OTA: в `build` может
оставаться бинарный файл от предыдущей успешной сборки.

## 3. Заменить бинарный файл OTA

Скопировать свежий `build/lvgl_porting.bin` в `releases/download`, заменив старый:

```powershell
Copy-Item -LiteralPath .\build\lvgl_porting.bin -Destination .\releases\download\lvgl_porting.bin -Force
```

Для OTA нужен именно `lvgl_porting.bin`. Файлы загрузчика, таблицы разделов
и объединённый образ вместо него использовать не нужно.

## 4. Обновить version.json

В `releases/download/version.json` указать **ту же версию**, с которой только
что собрана прошивка:

```json
{
  "version": "1.0.10"
}
```

Перед публикацией должны совпадать три значения: `PROJECT_VER`, версия
в собранной прошивке и `version` в JSON. Менять только JSON недостаточно.

## 5. Опубликовать обновление

После проверки отправить изменения в GitHub, в ветку `main`:

- `CMakeLists.txt` с новой версией;
- `releases/download/lvgl_porting.bin` со свежей прошивкой;
- `releases/download/version.json` с той же версией;
- изменения исходников, вошедшие в эту сборку.

Текущие OTA-адреса в `main/user/periphery/ota.h` читают файлы непосредственно
из `releases/download` в ветке `main` через `raw.githubusercontent.com`.
Создавать отдельный GitHub Release для этой схемы не требуется.
Бинарный файл и JSON публиковать одним коммитом.

После публикации на устройстве открыть раздел обновления прошивки,
проверить доступную версию и запустить OTA. После перезагрузки проверить
версию установленной прошивки.
