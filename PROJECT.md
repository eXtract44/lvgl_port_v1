# ESP32S3 Touch 7 — станция качества воздуха и погоды

Персональная умная станция на ESP32-S3: сенсорный монитор качества воздуха в помещении + погодный дисплей. Интерфейс полностью на немецком (стандарты UBA/DWD, немецкие праздники, данные по региону Дортмунд).

## Железо

| Компонент | Описание |
|---|---|
| Плата | Waveshare ESP32-S3 Touch LCD 7" (RGB 800×480) |
| I/O-расширитель | CH422G (в т.ч. TP_RST для GT911 — EXIO1) |
| Тач | GT911 |
| Подсветка | AP3032/MP3302 boost-драйвер, PWM на GPIO6 |
| Сенсоры (I²C) | SHT41 (T/RH), SGP30 (TVOC), SCD41 (NDIR CO₂, опционально) |

## Софт

- **Стек:** C, ESP-IDF v5.3.1, LVGL 8.4, FreeRTOS, cJSON, esp_https_ota, mbedtls
- **Среда:** Espressif IDE (Windows) / VS Code + ESP-IDF extension
- **Хранение:** NVS (настройки), SPIFFS (кэш ответов API)
- **OTA:** GitHub Releases (публичный репозиторий, raw-URL), проверка версии через `version.json`
- **Шрифты:** LVGL font converter, `--bpp 4` (не `--lcd`); FontAwesome 0xF000–0xF8FF

## Функции

- Дашборд LVGL из нескольких блоков
- Измерение T/RH, TVOC, CO₂ (при наличии SCD41)
- Погода и прогноз: Open-Meteo (модель `icon_eu`), текущие наблюдения — Bright Sky/DWD
- Управление WiFi, OTA-обновления, сохранение настроек в NVS
- Подсветка: режимы Manuell / Auto / Zeitplan, плавная рампа (±1%/тик, таймер 33 мс), границы Auto-режима (два слайдера)

### Две прошивки (compile-time `CONFIG_HAS_SCD41`)

- **SCD41 + SGP30:** реальный CO₂ (NDIR), оценка GUT/MITTEL/HOCH по UBA
- **Только SGP30:** основной сигнал — TVOC. eCO₂ с дисплея убран сознательно (расчётный, ненадёжный)

## Текущее состояние

| Задача | Статус |
|---|---|
| Dual-firmware (SCD41 / без) | практически готово |
| Зависание GT911 после долгого простоя | диагноз есть, стратегия восстановления спроектирована (NACK-счётчик → reset-task через CH422G → reinit + периодический ping); ждёт подтверждения драйвера, TP_RST и способа логирования |
| OTA: белые рамки на дисплее | двойной draw-buffer desync; фикс: обнуление стиля оверлея + двойной `lv_refr_now()` (или `memset` — после проверки `buffer_size`/`flush_cb`) |
| OTA: обрывы загрузки | сброс TLS-сессии на raw-CDN → partial HTTP download, retry-цикл |
| Мерцание подсветки ~55% duty | нестабильное питание на входе (плохой USB-контакт); план: PWM 10 кГц после проверки даташита AP3032 |

## Планы

- Автообновление (опрос ~2 ч) — отложено
- Геолокация по IP (`ip-api.com`) — спроектировано, не реализовано
- Праздники/каникулы DE (`openholidaysapi.org`) + кэш в SPIFFS — спроектировано, не реализовано
- Колонка дней недели с Пн первым в блоке времени
- BLE-сеть сенсорных узлов: ESP32-C3, BTHome advertising, регистрация по MAC, собственная печатная плата

## Накопленные правила (hardware learnings)

- **RGB-панель:** «безопасных» координат нет — DMA постоянно читает весь framebuffer; статичные белые границы = рассинхрон двойного буфера, не конфликт DMA.
- **Подсветка:** AP3032/MP3302 рассчитан на PWM 200 Гц–1 кГц; 60 кГц давал мерцание. Пульсации тока максимальны при D = 50% (`√(D·(1−D))`) — поэтому мерцание проявляется там первым при слабом питании.
- **LVGL память:** внутренний пул 48 КБ мал для градиентов → `heap_caps_malloc` (системная куча ~200–300 КБ), иначе крэши `allocate_item`.
- **GT911:** отдельный домен питания/сброса, soft-reboot ESP его не сбрасывает; для восстановления нужен явный импульс TP_RST через CH422G.
- **OTA:** двухслотовая схема переживает потерю питания; `esp_ota_mark_app_valid_cancel_rollback()` в `app_main()` обязателен.
- **Баг-паттерны:**
  - `backlight_set(0)`: формулы вида `30 + percent*70/100` оставляют подсветку включённой → нужен early return на 0.
  - Периодическая работа без побочных эффектов (`backlight_tick()`) — в начало LVGL-таймера, до early-return.
  - После `lv_obj_clean()` обнулять указатели виджетов в back/close-хендлерах (иначе крэш при повторном входе).
- **SGP30:** eCO₂ ≠ реальный CO₂ (вывод из H₂/TVOC), ненадёжен при немetabolических VOC.

## Принципы работы

- Сначала архитектура и подтверждение подхода, потом код
- Пошагово, с подтверждением каждого шага
- Точечные diff («найди / замени»); полные функции — только при множестве взаимосвязанных правок
- Без over-engineering
